## 一、背景

sandbox 使用 Linux 原生 `syscall.CLONE_NEWNET` 为每个任务进程创建独立的网络命名空间：

```go
// internal/runtime/osexec.go
sysProcAttr := &syscall.SysProcAttr{Setpgid: true}
if features.network && os.Geteuid() == 0 {
    sysProcAttr.Cloneflags |= syscall.CLONE_NEWNET
}
```

**效果**：任务进程默认完全无法访问网络（包括内网和外网）。

业务上，**Skills 脚本**需要访问外部 HTTP/gRPC 服务，但**沙箱内 Code** 的网络访问必须受控。

---

## 二、设计原则

1. **Code（沙箱内）**：网络访问受控，只能访问外网，禁止访问内网 IP
2. **Skills（沙箱内）**：同样受网络隔离约束，通过 SOCKS5 代理访问外部服务
3. **通信桥梁**：veth pair + SOCKS5 代理，由 `internal/proxy` 包实现

## 四、核心组件

### 4.1 NetworkProxy（`internal/proxy/network.go`）

NetworkProxy 负责管理沙箱的网络生命周期：

| 方法 | 职责 |
|------|------|
| `Setup(pid)` | 创建 veth pair，将 sandbox 端移入目标 netns，配置 IP 和 iptables |
| `Start(ctx)` | 启动 SOCKS5 代理服务器 |
| `Stop()` | 停止 SOCKS5 代理 |
| `Cleanup()` | 清理 veth 等网络资源 |
| `GetProxyEnv()` | 返回代理环境变量（`ALL_PROXY`、`HTTP_PROXY` 等）|

**Setup 流程：**

```
1. createVethPair()      → 创建 veth pair（宿主端 + sandbox 端）
2. configureHostVeth()   → 为宿主端配置 IP、启用接口
3. moveVethToNetns()     → 将 sandbox 端移入任务进程的 netns
4. configureSandboxVeth() → 在 sandbox netns 内：
   - 启用 lo
   - 重命名接口为 claw0
   - 配置 IP
   - 应用 iptables OUTPUT DROP 策略
5. NewSocks5Server()     → 在宿主端启动 SOCKS5 代理
```

**IP 分配策略：**

使用 `10.233.0.0/16` 网段，相邻对分配 `(2,3), (4,5), ... (252,253)`：

```go
// internal/proxy/network.go
func GenerateUniqueIPs(instanceID int) (bridgeIP, sandboxIP string) {
    // 避免网络地址(0)、广播地址(255)、无效地址(.256)
    // 每 octet3 最大 126 对，总计 256 * 126 = 32256 唯一对
    const pairsPerOctet = 126
    totalPairs := 256 * pairsPerOctet
    instanceID = ((instanceID - 1) % totalPairs) + 1
    octet3 := (instanceID - 1) / pairsPerOctet
    pairIdx := (instanceID - 1) % pairsPerOctet
    baseOctet := pairIdx*2 + 2 // 2~253
    sandboxIP = fmt.Sprintf("10.233.%d.%d", octet3, baseOctet)
    bridgeIP = fmt.Sprintf("10.233.%d.%d", octet3, baseOctet+1)
    return
}
```

### 4.2 SOCKS5 代理（`internal/proxy/socks5.go`）

标准 SOCKS5 协议实现，支持：

- **无认证模式**：`authNone`
- **CONNECT 命令**：仅支持 TCP 连接
- **地址类型**：IPv4、域名、IPv6
- **DNS 解析后二次检查**：防止 DNS rebinding 攻击

**连接处理流程：**

```
客户端 SOCKS5 请求
    ↓
Phase 1: Handshake（协商认证方法）
    ↓
Phase 2: Request（解析目标地址）
    ↓
IP 过滤检查（ipFilter.CheckHostWithPort）
    ↓
目标 IP 为私网 → 返回 repConnectionRefused（拒绝）
目标 IP 为公网 → Dial 连接目标
    ↓
返回 repSuccess
    ↓
bidi relay（双向数据转发）
```

### 4.3 IP 过滤器（`internal/proxy/ip_filter.go`）

两种过滤模式：

| 模式 | 说明 | 适用场景 |
|------|------|----------|
| **blacklist（默认）** | 阻止私网 CIDR，允许所有其他 IP | 通用外网访问 |
| **whitelist** | 仅允许指定的 IP:Port 组合 | 严格限制内部服务访问 |

**默认私网黑名单 CIDR：**

```go
var DefaultPrivateCIDRs = []string{
    "10.0.0.0/8",      // 私有 IPv4 (Class A)
    "172.16.0.0/12",   // 私有 IPv4 (Class B)
    "192.168.0.0/16",  // 私有 IPv4 (Class C)
    "127.0.0.0/8",     // 回环
    "169.254.0.0/16",  // 链路本地（云元数据）
    "0.0.0.0/8",       // 本网络
    "224.0.0.0/4",     // 组播
    "240.0.0.0/4",     // 保留
    "255.255.255.255/32", // 广播
    "::1/128",         // IPv6 回环
    "fc00::/7",        // IPv6 唯一本地
    "fe80::/10",       // IPv6 链路本地
    "ff00::/8",        // IPv6 组播
    "::/128",          // IPv6 未指定
}
```

**白名单配置示例：**

```go
rules := []proxy.AllowRule{
    {IP: net.ParseIP("8.8.8.8"), Port: 443},
}
filter, _ := proxy.NewWhitelistFilterWithPorts(rules)
netProxy.SetIPFilter(filter)
```

### 4.4 iptables 出站策略

sandbox netns 内应用以下 OUTPUT 规则：

| 规则 | 动作 | 说明 |
|------|------|------|
| `-P OUTPUT DROP` | 默认丢弃 | 所有出站流量默认拒绝 |
| `-o lo -j ACCEPT` | 允许回环 | lo 接口通信不受限 |
| `-m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT` | 允许响应 | 已建立连接的返回流量 |
| `-d <BridgeIP> -p tcp --dport <ProxyPort> -j ACCEPT` | 允许代理 | 仅允许访问 SOCKS5 代理 |
| `-p udp -j DROP` | 丢弃 UDP | 显式禁用 UDP 出站 |

> 原始 socket（`SOCK_RAW`）尝试直接发包时，`sendto` 返回 `EPERM`，无法绕过 OUTPUT DROP。

## 五、启动门控（`internal/runtime/start_gate.go`）

网络配置需要一定时间（veth 创建、IP 配置、iptables 规则下发），任务进程必须在网络就绪后才能开始执行。使用 pipe 机制实现启动门控：

```go
type commandStartGate struct {
    readPipe  *os.File
    writePipe *os.File
}
```

**工作流程：**

```
1. newCommandStartGate() → 创建 pipe
2. Wrap(command) → 包装命令："等待 pipe 读端收到数据后再 exec"
3. cmd.Start() → 子进程启动，阻塞在 pipe 读端
4. NetworkProxy.Setup() → 配置网络
5. waitForTCPReady() → 确认 SOCKS5 代理已监听
6. startGate.Release() → 向 pipe 写端写入数据
7. 子进程解除阻塞，开始执行实际命令
```

## 六、与 Runtime 集成

### 6.1 执行流程（`internal/runtime/osexec.go`）

```go
func executeCommand(ctx, spec, opts, features) (ExecResult, error) {
    // 1. 创建启动门控（如需要网络隔离）
    if features.network {
        startGate = newCommandStartGate()
        command = startGate.Wrap(command)
    }

    // 2. 配置 syscall.SysProcAttr
    sysProcAttr := &syscall.SysProcAttr{Setpgid: true}
    if features.network {
        sysProcAttr.Cloneflags |= syscall.CLONE_NEWNET  // 新建 netns
    }
    // Credential 在 exec 前降权到 runner UID（10001）
    sysProcAttr.Credential = &syscall.Credential{Uid: opts.RunnerUID, Gid: opts.RunnerGID}

    // 3. 创建 NetworkProxy
    cfg := proxy.DefaultNetworkConfig()
    cfg.BridgeIP, cfg.SandboxIP = proxy.GenerateUniqueIPs(instanceID)
    netProxy = proxy.NewNetworkProxy(cfg)
    cmd.Env = append(cmd.Env, netProxy.GetProxyEnv()...)  // 注入代理环境变量

    // 4. 启动进程
    cmd.Start()

    // 5. 配置网络
    netProxy.Setup(cmd.Process.Pid)
    go netProxy.Start(ctx)
    waitForTCPReady(proxyAddr)  // 等待 SOCKS5 就绪
    startGate.Release()         // 释放门控，任务开始执行

    // 6. 等待任务完成
    cmd.Wait()

    // 7. 清理
    netProxy.Stop()
    netProxy.Cleanup()
}
```

## 七、权限要求

网络隔离需要以下权限之一：

```bash
# 方式 1：root 运行
sudo ./claw

# 方式 2：能力设置
sudo setcap cap_net_admin,cap_sys_admin+ep ./claw
```

| 能力 | 用途 |
|------|------|
| `CAP_NET_ADMIN` | 创建 veth pair、配置 IP、移动接口到 netns、设置 iptables |
| `CAP_SYS_ADMIN` | `CLONE_NEWNET`（非 root 用户创建新 netns）|

**权限不足时的降级：**

当非 root 运行时，网络隔离自动跳过，任务进程使用容器默认网络。

## 八、安全边界总结

### 8.1 攻击向量覆盖

| 攻击向量 | 防护措施 | 实现位置 |
|---------|---------|---------|
| 沙箱内直接访问内网 | `CLONE_NEWNET` + iptables OUTPUT DROP | `internal/runtime/osexec.go` |
| DNS rebinding 打内网 | SOCKS5 代理解析 DNS 后二次检查 IP | `internal/proxy/socks5.go` |
| UDP 绕过 OUTPUT DROP | iptables `-p udp -j DROP` | `internal/proxy/network.go` |
| 原始 socket 绕过 | OUTPUT DROP 对所有出站生效 | `internal/proxy/network.go` |
| iptables 规则篡改 | `Credential` 降权到 runner UID（10001）| `internal/runtime/osexec.go` |
| 连接云元数据（169.254.169.254）| 内网 CIDR 黑名单覆盖 | `internal/proxy/ip_filter.go` |

### 8.2 已知局限

| 限制 | 说明 |
|------|------|
| UDP 出站完全禁用 | 当前 SOCKS5 仅支持 TCP CONNECT，UDP 通过 iptables 显式丢弃 |
| 需要 root/CAP_NET_ADMIN | 创建 veth pair 和配置 iptables 需要特权 |
| 单容器多任务共享 /tmp | 同一 clone 信任域内，风险可控 |
| veth 异常残留 | SIGKILL 时 cleanup 可能不执行，但 veth 名含 PID，不会无限增长 |
